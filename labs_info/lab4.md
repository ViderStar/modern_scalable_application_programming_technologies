## Задание

Эмулятор банкомата, работающий с банком из предыдущих работ; рабочий счёт — кредитный счёт ЛР3.

- Аутентификация: номер карты и PIN-код с клавиатуры; три неверных PIN-кода подряд —
  работа завершается.
- Меню: снять деньги, остаток кредитного счёта, остаток депозитного счёта*, платёж*,
  забрать карту (* — необязательные, реализованы).
- **Внутренний список**: банкомат копит введённые данные и отправляет банку всё содержимое
  списка одной транзакцией, после чего очищает его. Для следующей операции данные карты
  вводятся заново; номер карты эмулятор помнит.
- Снятие: сумма — неотрицательное целое; банк проверяет достаточность средств; чек по желанию.
- Остаток: предложение напечатать чек, затем состояние счёта, далее — продолжить или
  забрать карту.
- Платёж: оператор → номер из 10 цифр → сумма → подтверждение или ввод заново; чек
  печатается автоматически.

## Протокол «банк — банкомат»

`POST /api/atm/transactions` на сервисе кредитов. Запрос — список пар:

| Имя | Значение |
|---|---|
| `CARD` | номер карты, 16 цифр |
| `PIN` | PIN-код, 4 цифры |
| `OPERATION` | `AUTHORIZE`, `WITHDRAW`, `BALANCE`, `DEPOSIT_BALANCE`, `PAYMENT` |
| `AMOUNT` | сумма снятия или платежа |
| `OPERATOR`, `PHONE` | оператор связи и номер телефона |

Ответ: `status` (`OK`/`ERROR`), `code` (`WRONG_PIN`, `CARD_BLOCKED`, `INSUFFICIENT_FUNDS`, …),
`message` для экрана, `data` для чека. Банк проверяет карту и PIN-код в **каждой**
транзакции и не хранит состояние диалога.

## Автомат сеанса

```
INSERT_CARD → PIN → MENU ─┬─ AMOUNT ──────────────────────────→ RECEIPT_PROMPT → MENU
                          ├─ (остаток) ────────────────────────→ RECEIPT_PROMPT → RESULT
                          ├─ OPERATOR → PHONE → PAY_AMOUNT → CONFIRM → MESSAGE
                          └─ (забрать карту) → INSERT_CARD
```

Отказ банка по любой операции ведёт в `MESSAGE`; три неверных PIN-кода — в `INSERT_CARD`.

## Как устроено

- `AtmSession` (atm-service) — автомат и внутренний список; `enter`, `select`, `cancel`
  возвращают описание экрана. Интерфейс на Vue только рисует его.
- `AtmProcessor` (credit-service) — проверка карты и PIN-кода, операции через главную книгу.
  Снятие — проводки 2–3 кредитной схемы; платёж — с текущего счёта на счёт оператора 3012.
- PIN-код генерируется при выпуске карты, показывается один раз, хранится хешем BCrypt;
  после трёх ошибок карта блокируется банком, блокировку снимает «Перевыпустить PIN».
- **Демо-карты** — `DemoCards` в сервисе кредитов после старта заключает три договора и
  назначает картам PIN-коды из настройки `bank.demo`; список показан на странице банкомата.
- **Языки** — экраны и чеки формирует сервис на языке из `Accept-Language`
  (`messages*.properties` в atm-service), ответы банка приходят на том же языке.

## Сценарий демонстрации

1. `scripts/run-all.sh`; через несколько секунд на странице банкомата появятся демо-карты.
   Свою карту можно выпустить так: «Кредиты» → заключить договор → карта и PIN-код из
   «ПИН-конверта».
2. «Банкомат» → «Вставить» у демо-карты (или набрать номер), Enter → PIN-код, Enter.
3. Снять наличные → чек; остаток (PIN-код запрашивается заново); оплата связи.
4. Снять больше остатка → отказ банка. Три неверных PIN-кода → карта заблокирована.
5. «Счета» → в отчёте видны проводки снятия и счёт оператора 3012.

```bash
./mvnw -pl atm-service,credit-service -am verify
```
